  <p style="font-family:'Inter','Helvetica Neue',Arial,sans-serif;font-size:16px;line-height:1.55;color:#1f160e;margin:0 0 10px;">What matters if you&rsquo;re upgrading:</p>
  <ul style="font-family:'Inter','Helvetica Neue',Arial,sans-serif;font-size:15px;line-height:1.55;color:#1f160e;margin:0;padding-left:22px;"><li style="margin:0 0 8px;"><strong>Breaking: <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac start</code> and <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac dev</code> fold into <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac run</code>.</strong> Both are tombstoned. Serve with <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac run --serve</code>, dev with <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac run --dev</code>, and deploy with <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac scale deploy</code> now that <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">--scale</code> is gone.</li><li style="margin:0 0 8px;"><strong>Breaking: type checking runs on every compilation.</strong> <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac build --no_typecheck</code> and the other escape hatches are gone, so a type error is a compile failure instead of the runtime crash it used to become.</li><li style="margin:0 0 8px;"><strong>Breaking: fixed-width numerics are real types.</strong> <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">i8</code> through <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">f64</code> follow one value-preserving lattice on every lane, so passing an <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">int</code> into a sized parameter now needs a cast like <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">i32(n)</code>.</li><li style="margin:0 0 8px;"><strong>Breaking: <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac test</code> has its own runner.</strong> pytest is out of the binary. The project suite went from 76s to 7.5s wall.</li><li style="margin:0 0 8px;"><strong>Breaking: a keyword is never an identifier.</strong> Use the backtick escape, and importing typing spellings Jac already provides is a hard error.</li><li style="margin:0;"><strong>New: <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac db list</code>, <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac db drop</code> and <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac db prune</code>.</strong> Every database the runtime creates now records its owner, so a cluster is finally inspectable and reclaimable. <code style="font-family:'SFMono-Regular',Consolas,monospace;font-size:0.9em;background:#ece7db;padding:1px 5px;border-radius:4px;">jac seal</code> gets its own front door too.</li></ul>
